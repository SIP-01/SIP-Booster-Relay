# Security Audit — SIP-01/SIP-Booster-Relay — 2026-10-20

## Summary
Serverless Nostr/SIP-01 relay on Cloudflare Workers + D1 + Durable Objects, forked from Spl0itable/nosflare at v7.9.45 (UPSTREAM.md documents lineage honestly). The fork is security-*ahead* of upstream: it fixed upstream's unauthenticated `?npub=` pay-to-relay hole (now requires a verified kind-9735 zap receipt), removed an outbound-WS SSRF surface in NIP-05 validation, pins deploy bundles to immutable commits, and isolates the hosted deploy service into its own Worker. Ingestion hardening is thorough (id-hash + Schnorr verification, shape checks before crypto, future-created_at rejection, SIP-01 §12.4 validation, token-bucket rate limits, query-cost prechecks, NEG budgets). All SQL parameterized. No committed secrets. Findings: 0 CRITICAL / 0 HIGH / 2 MEDIUM / 2 LOW.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| SBR-M1 | MEDIUM | src/config.ts (`DEPLOY_BUNDLE_SHA256 = ""`) | Hosted deploy service fetches the CI-built `worker.js` pinned to an immutable commit (good) but the SHA-256 bundle-hash enforcement is empty by default, so a compromised GitHub ref/RAW response would provision a tampered relay into customer accounts. The config comment itself recommends setting it for production. | Publish the hash per release and ship it non-empty; fail closed when empty in service mode. |
| SBR-M2 | MEDIUM | src/config.ts (defaults) | Stock config ships the original author's `SERVICE_OWNER_PUBKEY`, `relayNpub`, and NIP-11 pubkey baked in. A lazy operator who enables the deploy service without editing config grants the upstream author `/admin` (NIP-98 owner-gated) access and routes payments to the author's npub. Fail-open-by-default for attribution, though DEPLOY_SERVICE_ENABLED=false mitigates. | Refuse service startup when SERVICE_OWNER_PUBKEY equals the shipped default; add a first-run checklist warning. |
| SBR-L1 | LOW | src/relay-worker.ts | `Access-Control-Allow-Origin: *` on `/api/*`, NIP-11, NIP-05, payment endpoints. All are unauthenticated public read/self-service endpoints with no cookies, so risk is low; any future credentialed endpoint must not inherit `jsonResponse`. | Document the invariant; consider allowlisting if admin APIs move onto this worker. |
| SBR-L2 | LOW | repo root | `service-worker.js` (322 KB) and `worker.js` (357 KB) committed build artifacts — divergence risk between source and bundle, and unauditable diff surface. | Build in CI, deploy from CI artifacts; .gitignore bundles or attach to releases. |

## Secrets Check
